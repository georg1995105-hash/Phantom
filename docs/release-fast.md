# PHANTOM VPN: быстрый официальный релиз

Постоянный регламент владельца от 23.11.2026. При новом чате ИИ должен прочесть этот файл вместе с [AGENTS.md](../AGENTS.md), а не повторять историю старых сообщений.

Два канала обновлений в одном APK: [docs/ota-channels.md](ota-channels.md). `release_channel=stable` (по умолчанию) публикует обычный Release; `release_channel=beta` — GitHub Prerelease с общей официальной подписью, но не меняет постоянную ссылку на стабильную версию. `versionCode` возрастает через оба канала.

Поддерживаются Delta OTA и один установочный APK: [docs/delta-ota.md](delta-ota.md). В официальном QUICK workflow после production-подписи дополнительно генерируются проверенные побайтово патчи предыдущей стабильной и подходящей бета-версии. Публикация сохраняет `phantom-universal-release.apk` и неизменный постоянный URL. Любая ошибка восстановления патча на клиенте — автоматический полный APK; менять ключ подписи или делать второй пакет нельзя.

## По умолчанию: QUICK

Цель — после обычной правки быстро выдать **один официальный APK, подписанный production-сертификатом**, который обновляет уже установленную Phantom без удаления пользовательских данных.

1. Сверить фактические `main`, последний GitHub Release, существующие ветки/PR и изменения в нужных файлах. Делать только адресные тесты по зоне риска. **Не запускать полный длительный CI без прямой просьбы владельца.**
2. Внести исправление, увеличить `versionCode`, поставить новую `versionName` и заголовок `# PHANTOM VPN X.Y.Z` в `RELEASE_NOTES.md`. Сохранить `applicationId=xyz.wraithnet.phantom` и неизменный сертификат подписи.
3. Внести проверенный SHA в `main`. Одним `workflow_dispatch` запустить `.github/workflows/quick-apk.yml` (`Quick signed universal APK`) на ветке `main`. Поле `source_sha` пустое — workflow берёт зафиксированный SHA при запуске. `publish_release=true` — сборка, изолированная production-подпись, проверки и публикация одним процессом.
4. Убедиться, что workflow `success`, новый Release `draft=false`, `prerelease=false`, стоит последним, релизный `target_commitish` соответствует исходному SHA, у него один `phantom-universal-release.apk` и SHA-256 совпадает с загруженным подписанным артефактом. Не считать только запуск Actions успешным релизом.
5. Дать пользователю **одну постоянную ссылку**, версию и кратко сообщить, что проверено, а что нет. Не рекомендовать удаление приложения для обновления.

**Постоянная ссылка (домен GitHub):**

```text
https://github.com/georg1995105-hash/Phantom/releases/latest/download/phantom-universal-release.apk
```

Ссылка остаётся прежней при смене версий. На сайте [app.veor.pro](https://app.veor.pro/) она используется в главной и нижней кнопке. Исходник сайта — ветка `gh-pages`, `index.html` и `CNAME`. Отдельные ARM64/ARM32/x86 сборки не публикуются, поэтому на сайте их предлагать нельзя. Надпись текущей версии на сайте запрашивается по GitHub API; при недоступности API ссылка на APK всё равно работает.

**Официальный сертификат подписи (публичный отпечаток, не секрет):** SHA-256 `86bc0b32349dec451d94ed402a1addc1ad3ec6084439cb8dc05aee88e5d8a4ca`. Ключ и пароли хранятся только в GitHub Actions secrets. Релиз обязательно включает `arm64-v8a`, `armeabi-v7a`, `x86`, `x86_64`. Не менять ключ и не публиковать PR/CI-ключ вместо него.

## Если нужна только подписанная сборка без релиза

В том же workflow установить `publish_release=false`. Он создаст **подписанный артефакт для ручной проверки**, но обновление по воздуху не появится. Не путать это со стабильным релизом. Старый `publish-quick-ota.yml` оставить как аварийный резерв, но **не запускать вторым шагом по умолчанию**.

## Полный аудит (FULL)

Только по прямому запросу владельца: общий `build.yml` со всеми Android-инструментальными проверками, телевизором и пультом, 16-KiB, JNI, восстановлением данных и обновлением поверх предыдущей версии. Если вне этой просьбы изменяется VPN core, криптографическая безопасность, OTA, подпись, совместимость хранения или миграция — выполнить **необходимые адресные критические** проверки, не выпускать заведомо опасный или неустанавливаемый пакет. Для обычного текста, карточки, отступов и иконок не тратить часы на полную матрицу.

## Правило завершения задачи

Не заканчивать на `commit` или `PR` и не говорить «APK готов», если опубликован лишь временный артефакт. Для прямой задачи обновления итог — официальный универсальный APK в Releases и работоспособная постоянная ссылка. Если какая-либо проверка действительно не прошла, указать это отдельно, не скрывая сбой и не представляя невыполненные тесты как успешные. Действующий стабильный релиз не заменять debug-пакетом.
