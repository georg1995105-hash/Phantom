1. На CONTROL в указанном каталоге выполнить `git status --porcelain=v1 -uall`, `git diff --cached --stat`, `git diff --stat`, `git log -3 --oneline`. Сохранить вывод в отчёт.

Убедиться, что все необходимые исходники, ресурсы, лицензии HeliBoard, Gradle wrapper, конфиги сборки и файлы собственного проекта отслеживаются git, а `.gradle/`, `build/`, `app/build/`, `.cxx/`, SDK/NDK/AVD, кэши и ключи/токены **не попадают в git**. 3. Не удаляя и не перезаписывая ничего, создать **локальный коммит** с помощью `git -c user.name="SmartVoice Droid" -c user.email="factory-droid@local.invalid" commit -m "Implement SmartVoiceKeyboard Android IME v0.1.0"` после `git add` только нужных путей. 4. Сохранить SHA HEAD; создать **Git bundle** текущей ветки в отдельной временной папке с местом: `git bundle create <path>/SmartVoiceKeyboard-source.bundle main`. 5. Сравнить рабочую копию с `origin/main` и проверить историю: на момент переноса GitHub может получить новые документационные коммиты. Использовать `git fetch` и безопасный merge/rebase, **не** `reset --hard`, не force-push и не перезаписывать удалённые изменения.

## Фаза 2. Фактический перенос

Основной вариант — безопасная загрузка подготовленной исходной ветки в приватный GitHub. **Deploy key на CONTROL read-only**: не пытаться push без авторизации и не менять права/ключи самостоятельно. 

- Если у пользователя предоставлен отдельный законный, ограниченный способ push — использовать его с разрешения, не размещая токены в командных строках, логах, чатах или репозитории.
- Иначе безопасно экспортировать `.bundle` и APK через доступный пользователю защищённый файловый канал/вложения Factory, чтобы их можно было загрузить в GitHub другим авторизованным инструментом. Не делать общедоступные HTTP-ссылки и не открывать новые порты CONTROL ради передачи.
- После загрузки проверить наличие исходников, ресурсы и историю коммитов на GitHub в ветке `main`, `git ls-remote`, сверить SHA и отсутствие секретов/лишних артефактов.

## Фаза 3. GitHub Actions вместо CONTROL

Настроить workflow на `ubuntu-latest`, JDK/Android SDK и Gradle, совместимые с *фактическим* исходным проектом, который был проверен на CONTROL. Не угадывать task/flavor: получить из `./gradlew tasks` либо реальных файлов Gradle. CI: clean checkout, сборка debug APK, юнит-тесты, сохранение APK в private Actions artifacts, вывод SHA-256. Не хранить собранные APK в коммитах репозитория. Для GPLv3-производной сохранить лицензионные уведомления.

**Критерии успешного переноса:** исходный код и история коммитов доступны в приватном GitHub; Actions успешно собирает тот же вариант APK и проходит тесты; полученный artifact скачиваем; SHA/размеры и сведения о сборке задокументированы; воспроизводимая сборка не зависит от CONTROL. SHA итогового APK может отличаться от старого из-за среды/времени/подписи — это не ошибка само по себе. Отдельно проверить IME на реальном устройстве после установки; эмулятор не доказывает рабочий голос.
