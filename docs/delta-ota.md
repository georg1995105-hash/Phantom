# Delta OTA — однопакетные обновления Phantom VPN

Решение владельца: не скачивать каждый раз весь универсальный APK (184+ МБ), не усложнять установку и не создавать отдельное приложение.

## Формат и надёжность

- Один подписанный официальный `phantom-universal-release.apk` остаётся основной установкой и постоянной ссылкой для `app.veor.pro`, Android, Android TV и новых клиентов.
- В GitHub Releases дополнительно публикуются маленькие `phantom-delta-from-vX.Y.Z.apkdelta` (или `vX.Y.Z-beta.N`). Патч строится *между точно подписанными APK*, а не отдельными пакетами.
- `scripts/build_apk_delta.py` находит неизменившиеся ZIP-части (включая крупные библиотеки и базы) и записывает операции COPY и INSERT с длиной и смещением. Результат проверяется побайтово на стороне CI. Если патч 80% размера APK или больше, он не публикуется.
- Android `PhantomDelta` сверяет SHA-256 **установленного APK** с патчем, размер и SHA-256 целевого APK с независимым GitHub release asset, ограничивает длины операций и восстанавливает точную копию уже подписанного APK. `PhantomUpdates.verifyApk` после восстановления проверяет packageName, версию, возрастающий versionCode и идентичный сертификат.
- Патч выбирается **только для точной установленной версии**. Любая ошибка скачивания, отсутствующий патч, повреждение данных, неправильный сертификат или неподходящий base.apk ведут к обычной полной загрузке и проверке, без удаления приложения.
- Один и тот же механизм работает со стабильным и бета-каналом. При отключении беты во время загрузки старое бета-обновление не устанавливается.

## Формат PHDELTA1

`MAGIC 8` = `PHDELTA1`; `uint64_be base_size`, `uint64_be target_size`, `32 bytes old SHA-256`, `32 bytes new SHA-256`, `uint32_be ops`. Далее COPY: `0, uint64_be offset, uint32_be length`. INSERT: `1, uint32_be length, literal bytes`. Без распаковки или выполнения кода из патча. Размер и количество операций ограничены. Kotlin/Android и Python/CI применяют одну схему.

## Публикация и обновление

Workflow `.github/workflows/quick-apk.yml` с `release_channel=stable` или `beta`:

1. Компилирует APK; отдельно подписывает production-ключом, проверяет сертификат.
2. В изолированной read-only job `delta` получает APK до трёх последних стабильных версий и последней подходящей беты, генерирует и проверяет патчи. Это даёт возможность пропустить несколько обновлений и перейти на новый выпуск с небольшим патчем.
3. Публикует **один полный APK** и дополнительные патчи как assets того же GitHub Release. Стабильная постоянная ссылка остаётся прежней; бета — prerelease.
4. Проверяет SHA-256 опубликованного APK и всех патчей.
5. На клиенте по кнопке «Обновить» патч скачивается и восстанавливается автоматически. Android может запросить подтверждение системной установки. При выдаче разрешения «Установка неизвестных приложений» пользователь возвращается в Phantom, и установка продолжается без повторного нажатия.

**Первый переход на 0.3.25 с 0.3.24 — полноценный APK**, потому что на старой версии ещё нет Delta-клиента. Уже с 0.3.25 новые выпуски могут скачиваться маленьким патчем.

## Проверки

`python3 -m unittest discover -s scripts -p test_apk_delta.py`; `:app:testDebugUnitTest` с `PhantomDeltaTest` и `PhantomUpdatesVersionTest`; компиляция и официальный ключ в CI. Размеры реальных патчей нужно измерять **по assets релиза**, а не обещать фиксированное количество МБ. Полный Android/TV аудит — по прямому запросу владельца; адресные регрессионные проверки OTA обязательны.
